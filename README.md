# DCL スタンプラリー (stamp-rally)

TikTok LIVE ライバー向けスタンプラリー（ビギナー / RISE）。
各ライバーの個別ページを **1枚のHTMLテンプレ + ライバー別JSON** で配信する。

- 公開URL: `https://dcl-events.github.io/stamp-rally/?id=<クリエイターID>`
- 成果 = 個別加点（自動・バックステージ由来）／課題 = オールクリアで満額（自己申告）
- 獲得ポイントは今後ビギナー/RISEランキングへ合算予定

## 構成
- `docs/index.html` … データ駆動テンプレ（?id= でJSONを読む）
- `docs/data/<ID>.json` … ライバー別データ（自動生成）
- `config/thresholds.json` … しきい値・ポイントの正本
- `tools/gen.py` … 成果(クリエイターデータ_Claude)＋課題(課題申告シート_Claude)→ JSON生成【Actionsで日次】
- `tools/gen_tasksheet.py` … 課題申告シートの名簿マージ更新（申告セル温存・卒業フラグ）【ローカル・ランキング日次の後段】

## 課題申告シートの列（2026-09-02 更新）
対象月は **creator_data の「データ期間」** が正本。backstage は約2日遅れなので
`今日(UTC)-2日` が属する月が対象月＝**月初1〜2日はまだ前月**（9/3の朝から9月分に切替）。

| 列 | 名前 | 誰が入れるか | 内容 |
|---|---|---|---|
| A〜F | 識別・ラリー | 自動 | ライバー名/ID/ユーザー名/CM/バックステージ/ラリー |
| G | 参加状況 | 自動 | `🟢 9月 参加中` / `🎓 8月まで RISE卒業` / `⚪️ 8月まで ビギナー対象外` |
| H | 個別URL | 自動 | ライバーに送るURL |
| I〜P | 課題8項目 | **人が入力** | 達成日を入れる。`—` は非該当。スクリプトは**この列を書き換えない** |
| Q | 初回参加月 | 自動 | 初めて名簿に載った月（以後ずっと温存） |
| R | 最終参加月 | 自動 | 最後に名簿に載っていた月（在籍中は対象月に追従／離脱で凍結） |
| S | 配信状況 | 自動 | `🟢 配信中（12日/45.2h）` / `⏸ 判定待ち` / `🔴 ◯月は未配信（先月…）` / `⚫️ 名簿なし` |
| T | URL送付 | 自動 | `送る` / `保留（未配信）` / `不要（◯月で終了）` / `要確認（名簿なし）` |

- **「◯月の対象者」を出す** → R列(最終参加月)でフィルタ。継続期間はQ〜Rで分かる。
- **URLを送る人だけ絞る** → T列が `送る` の行。
- 月初は当月ゼロが正常なので、対象月の経過が `GRACE_DAYS`(既定7日) 以内は
  配信ゼロを `⏸ 判定待ち` にして誤検知を防ぐ（`tools/gen_tasksheet.py` 冒頭で変更可）。
- 名簿(ID集合)と見出しが変わらない限り **A〜H と Q〜T だけを部分更新**する＝
  人が入力中の課題列を巻き込まない。名簿が動いた日だけ並べ直して全面書き込み。

## 自動化
- GitHub Actions が毎日 `gen.py` を実行 → `docs/data/*.json` を更新 → Pages公開（PC不要）
- サービスアカウントJSONはリポジトリ Secret `GOOGLE_SERVICE_ACCOUNT` に格納

## 課題は「通年温存」（2026-09-02 決定）
成果は**対象月の実績**（月が替わればゼロから）だが、**課題の申告は月をまたいでも消さない＝一度クリアすれば確定**。
ギフトギャラリー/プロフィール/オープンチャットのような一発ネタが主なので月次リセットはしない。
ページ上も 成果=「◯年◯月の実績」／課題=「通年・一度クリアで確定」と明示する。
